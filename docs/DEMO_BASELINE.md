# 《我要上天》Demo 基线

## 已确认方向

- 类型：2D 像素风生存、防守与探索游戏。
- 视觉：颜色清爽、明亮、通透；可参考《潜水员戴夫》的层次与可读性，但不复制素材。
- 视角：采用约 35°–45°的 3/4 俯视表现，地面纵向压缩，角色和 UI 保持竖直，不做真正旋转的等距摄像机。
- 世界：包含陆地、天空、海洋和海底。
- 地图：画面表现为连续大地图，技术上按图层和区块组织，不使用传统重复瓦片铺满画面。
- 交互：植物不是纯背景；玩家进入高草后，本人仍以半透明看到自己，其他玩家完全看不到该角色。
- 长期方向：多人在线联机。

## 第一版 Demo

第一版只做原始时代的单人陆地闭环：

1. 角色可在连续地图上移动。
2. 镜头跟随角色并限制在世界边界内。
3. 地图保留基础、装饰植物、互动植物、角色与建筑、前景遮挡、玩法元数据六层结构。
4. 玩家进入或离开草丛时，隐藏状态正确变化。
5. 镜头拉远并向角色前方偏移，场景通过地面压缩、投影和物体侧面形成纵深感。

逻辑世界尺寸为 6144 x 6144，区块基准为 1024 x 1024。当前地图是程序绘制的占位画面，用于验证尺度和交互，不是最终美术。

## 暂缓内容

- 天空、海洋与海底的完整玩法。
- 多人网络同步尚未实现；草丛可见性规则已经固化，联机时必须由服务器权威判定。
- 经济、建造、袭击、赛季与商业化系统。
- 正式大地图绘制和完整角色动画。

## 风险与独立判断

- “整张大地图”适合作为视觉目标，但不应作为单张 6144 x 6144 纹理一次性常驻内存；正式资源仍需分层、分区加载。
- 多人地图大小本身不是首要性能瓶颈；同步对象数量、更新频率、碰撞和可见范围更关键。
- 远端玩家隐藏不能只调用客户端的 `visible = false`；服务器还应停止向无权观察的客户端发送该玩家的位置更新，否则作弊客户端仍能读到坐标。
- 攻击、受伤或双方进入同一片草丛时是否强制暴露，会直接影响平衡，目前尚未锁定。
- 在核心移动与互动手感没有验证前扩展时代、联网和海陆空内容，会显著增加返工成本。
- 时代版本的完整拆分尚未锁定。当前只确认原始时代 Demo，后续应以策划表中的资源链、建筑链和敌人链为依据再定版本边界。

## 验收标准

- Godot 4.7.2 能无错误加载并运行 `main.tscn`。
- 方向键和 WASD 均可移动角色。
- 进入任意草丛时 HUD 显示“草丛隐蔽”，离开全部草丛后恢复“可见”。
- 本地玩家在草丛中保持半透明可见；同一隐藏状态用于远端角色时，角色节点不渲染。
- 场景树能清楚区分各地图层，后续替换正式美术时不需要重写玩家交互。
